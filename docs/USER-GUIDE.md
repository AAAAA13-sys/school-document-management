# Staff guide

Sign in with the staff email and password supplied by your administrator. Five failed sign-in submissions per minute per email/IP are throttled, with an additional IP limit. Inactive accounts cannot sign in and lose existing sessions. Sign out from the sidebar. My account changes your password and signs out your other sessions; contact an administrator to change your name, email, role or source.

## Workspaces and documents

Internal documents are readable by active Staff and Admins in their assigned ERP source and by Super Admin. Confidential documents are visible to their owner, the Admin of that source, Super Admin and explicit document recipients; Staff need ownership or an explicit document grant. Restricted documents are visible only to their owner, Super Admin and explicit document recipients. Editing and deleting remain limited to owned documents; an Editor grant permits editing content but not deleting. Named shares and folder grants may cross source boundaries, but folder grants widen Internal access only and ordinary workspace access stays inside the assigned source. Administrators manage their source; Super Admin has read-only oversight of all four sources and the full audit log, except for Restricted document sharing. No student DMS accounts are supported.

Upload document accepts a supported PDF, Office file, text/CSV or PNG/JPEG up to 10 MB, validated by actual content. Choose a classification (the upload dialog preselects Confidential) and optional folder/reference. You may classify your own upload at any level. The document is saved immediately as Pending, then ClamAV runs in the background. Keep the details page open to see the real scan status update. Failed versions retry automatically; Quarantined versions remain blocked. Contact an administrator if a version stays blocked. There is no manual Scan button.

Upload folder imports up to 50 files and their nested folder structure. Select a destination folder first if needed. Invalid files/path names reject the batch. A partial server conflict identifies the affected paths; retry the same form to resume with its original submission key. Do not reload a failed form before retrying if you need that key preserved.

Open a document to see immutable earlier versions, metadata, comments and activity. Upload new version preserves every prior file; competing edits require a reload. Downloads are allowed only after Clean and a fresh checksum check. Encrypted or unscannable files remain blocked. A scan result does not approve employment, payroll, enrollment or admission business decisions.

Admins create folders, open a folder and use Edit folder to rename/move it; Staff cannot create or manage folders. Cycles and destinations outside the actor's source are rejected. Rename or move document is available to its owner (and an Admin managing Internal/Confidential documents in that source); Restricted documents can only be managed by their owner. An Editor grant can rename but cannot move. Star files for quick access. Trash blocks downloads but preserves all versions; restore from Trash. There is no permanent-delete action.

Moving an Internal document into another shared folder changes who can open it, because Internal access is inherited from the folder. Confidential and Restricted documents require an explicit document grant, so a folder grant never exposes them. If the destination would give more people access, DMS asks you to confirm the move first and then records the change in the audit trail. Moving a document out of a shared folder removes that inherited Internal access. Earlier versions, comments, stars and audit records are never changed by a move.

## Sharing and history

Admins share Internal or Confidential documents they manage with named active staff in the same school/campus. Only Super Admin can create or revoke a share on a Restricted document; an Admin cannot share Restricted even when the Admin owns it. Viewer downloads; Commenter also comments (up to 2,000 characters); Editor also renames and uploads new versions. Editors cannot move, trash, reshare or change classification. A sharer can pin a Viewer/Commenter to one version, set an expiry, or revoke access. Pinned grants never expose another version through the download endpoint. Office/admin source access remains independent of an optional share.

Admins can share folders with the same Viewer/Commenter/Editor levels. Everyone granted on a folder can open it and every folder inside it, and inherits that permission for Internal documents there. Folder grants do not expose Confidential or Restricted documents; those require an explicit document grant. An explicit document grant always wins over folder inheritance, and the nearest folder grant wins over a more distant one. Inherited Editors can rename and add versions but still cannot move, trash, reshare or change classification. Revoking a folder grant removes inherited access immediately and leaves independent document grants in place; expiry works the same way. A folder grant may cross ERP sources; the recipient sees the shared Internal documents in Shared with me, while the source workspace itself remains closed. Moving a document is an owner action (or an Admin managing Internal/Confidential documents in the source), so the destination must be a folder the actor owns or manages.

Received history shows immutable ERP receipts. Current records shows the newest received revision, including deletion tombstones. Older events are preserved without replacing a newer snapshot. These screens do not edit the originating ERP. Admins see source-scoped history; Staff cannot inspect source history.

## Administration

Staff accounts creates, edits, activates/deactivates and changes roles. Super Admin can manage every account; an Admin can manage Staff only in its assigned source and cannot manage Admins or Super Admins. New accounts inherit the administrator's school/campus. Set a temporary strong password and ask the person to change it under My account. Editing an existing account leaves the password unchanged when blank. Password resets and deactivation revoke older sessions. Self-demotion and self-deactivation are rejected. Public registration is unavailable. A deactivated account cannot open any document, folder or inherited grant immediately; its existing grants and audit history are retained, and reactivation restores only the grants that were not revoked in the meantime.

ERP connectors creates one independently revocable token per source identity. Copy the raw token once and give it securely to that ERP team; it is never displayed again. Token hashes, not raw tokens, are stored. Connectors cannot administer staff or cross source/school/campus boundaries. Multiple connector identities for the same source share event/submission idempotency.

File security lists blocked versions. It does not offer a release/bypass button. Audit trail records uploads, scans, downloads, history intake, sharing and account/connector changes. An Admin's audit view omits entries for documents outside that Admin's classification visibility; Super Admin sees the full scoped audit. The notification popover explains scanning; it is not a delivery/alert service. External alerts and retention policies remain open SDD decisions.
